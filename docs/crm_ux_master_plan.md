# CRM UX刷新 全体指示書（司令塔ドキュメント）

このドキュメントは、CRMのUX改善（実サービス相当への刷新）全体の設計方針・原則・フェーズ計画を定める。
各フェーズの実装は別途「細かい分割指示」で与えるが、**常にこの全体指示を前提として作業する**こと。詳細な改善根拠は `crm_ux_improvement_proposal.md`（UX改善提案書）を参照。

## ゴール
主要CRM/SFA（Salesforce / Mazrica・Senses / GENIEE / ネクストSFA 等）と同等のユーザビリティに引き上げる。MUST＋SHOULD を実装する。

## 対象リポジトリと役割
- `laravel-business-template`（共通基盤）：共通デザインシステム・共通UI部品・マスタUIをここに構築。全システムの土台。
- `crm-sales`（CRM本体）：共通部品を使って画面を刷新。金額・集計ロジックには手を入れない（既存の正確性を維持）。
- `crm-demo-static`（静的デモ）：本体の新デザインに追随。

## 設計原則（全フェーズ共通）
1. **共通部品を先に作り、各画面はそれを組み合わせる**（画面ごとの個別実装を避ける）。
2. すべての部品は**テーマ差し替え機構（.envの配色・サービス名）と連動**。
3. **状態保持**：一覧の検索条件・ソートは前回状態を保持し、保存ビューで呼び出せる。
4. **日付は相対（今月/今四半期/今年度/過去N日）＋カスタム期間**の両対応。相対は月替わりで手動更新不要。
5. **画面遷移を減らす**：詳細・編集はモーダルまたは1ページ集約で完結。
6. **アクセシビリティ配慮**：キーボード操作・フォーカス・prefers-reduced-motion。既存の共通基盤の品質水準（Pint/Larastan/PHPUnit・CI）を維持し、各フェーズで `composer ci` を通す。
7. **金額・税・集計の既存ロジックは変更しない**（UIの刷新であって計算の変更ではない）。

## 共通UI部品の一覧（フェーズ1で構築）
- 左サイドナビゲーション（折りたたみ・セクション見出し・現在地ハイライト・パンくず）
- ボタン（primary / secondary / danger / ghost、サイズ、無効・ローディング）
- フォーム部品（テキスト/数値/日付/セレクト/チェック/ラジオ、必須・エラー表示）
- コンボボックス（入力で候補を絞るインクリメンタル検索セレクト）
- モーダル（詳細 / 編集 / 確認ダイアログ）
- 日付範囲ピッカー（相対プリセット＋カスタム開始〜終了）
- テーブル（ソート・行クリック・空状態・ローディング）
- バッジ／ステータスチップ、トースト通知、ページネーション、タブ、カード、KPIカード
- Blade コンポーネント＋Alpine.js で実装。マジックストリングを避け、再利用しやすい形に。

## フェーズ計画
### フェーズ1：共通デザインシステム（laravel-business-template）
- 1-A 左サイドナビゲーション
- 1-B 基本UI部品（ボタン/フォーム/バッジ/トースト/ページネーション/タブ/カード/KPIカード）
- 1-C コンボボックス（インクリメンタル検索）
- 1-D モーダル（詳細/編集/確認）
- 1-E 日付範囲ピッカー（相対＋カスタム）
- 1-F テーブル部品＋テーマ連動の最終確認
- 完了条件：デモ用の画面（コンポーネントカタログ的なページ）で各部品が動作し、テーマ差し替えが効き、`composer ci` が通る。

### フェーズ2：マスタUIの刷新（laravel-business-template）
- 2-A マスタのハブ画面（カード型の入口）
- 2-B 一覧の行クリック→モーダル詳細→編集・削除
- 完了条件：ハブから各マスタへ入れ、行クリックでモーダル編集・削除ができる。

### フェーズ3：CRM本体の改修（crm-sales）
- 3-A 左サイドナビ・共通部品を全画面に適用
- 3-B 商談一覧：期間フィルタ（基準日=予定クローズ日/受注日の切替＋相対＋カスタム）＋両日付の列表示
- 3-C 商談一覧：顧客・営業担当をコンボボックス化
- 3-D 商談一覧：検索条件・ソートの状態保持＋保存ビュー（マイビュー）
- 3-E 商談一覧：上部サマリ強化（ステータス別内訳バー）
- 3-F 商談：カンバン（パイプライン）表示をタブで追加（列ごと件数・金額、確度フィルタ）
- 3-G 商談詳細：1ページ集約の整理
- 完了条件：上記が動作し、金額・集計の既存テストが引き続き通る。`composer ci` 通過。

### フェーズ4：静的デモの追随（crm-demo-static）
- 4-A 本体の新デザイン（左ナビ・共通部品・新一覧・カンバン・マスタUI）に静的デモを合わせる
- 完了条件：静的デモが本体と同じ世界観・レイアウトで、代表画面が遷移する。

## 進め方
- フェーズ1 → 2 → 3 → 4 の順。各フェーズ内は細かい分割指示で1項目ずつ進め、完了ごとに動作確認・報告してから次へ。
- 各項目の実装後は必ず `composer ci`（該当リポジトリ）を通し、変更をコミットする。
- 迷う設計判断が出たら、勝手に決めず選択肢を提示して確認を求める。
